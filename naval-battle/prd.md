# PRD：土豆海战棋（H5 单人版）

## 1. 项目概述

项目名称：`土豆海战棋`

项目类型：手机竖屏 H5 单机小游戏

目标：

* 先生成一个可直接运行的 H5 项目
* 优先保证手机浏览器可玩
* 不接入后端
* 不接入账号系统
* 不接入联网
* 当前版本只实现**人机对战**
* 不实现双人对战
* 不引入 AI，大部分机器行为使用预设规则和随机策略

## 2. 技术栈与工程要求

本项目必须使用前端技术栈实现，生成完整 H5 工程。

技术栈固定为：

* `React`
* `TypeScript`
* `Vite`

实现要求：

* 必须生成完整工程目录
* 必须包含 `package.json`
* 必须包含 `vite.config.ts`
* 必须包含 `index.html`
* 必须包含 `src/` 目录
* 必须支持：

  * `npm install`
  * `npm run dev`
  * `npm run build`

* 构建后产物为纯前端静态资源
* 不需要 Node 服务端
* 不需要数据库
* 所有数据使用浏览器本地存储保存
* 所有界面文案必须使用简体中文
* 所有代码与文档统一使用 UTF-8 编码

## 6. 游戏基础规则

这是一个简化版海战棋单机游戏。

### 6.1 棋盘

* 敌我双方各有一个 `10 × 10` 格盘
* 所有判定都基于整格
* 不允许半格摆放
* 不允许半格点击

### 6.2 舰船

每方共有 3 艘舰船：

* 大型舰：长度 `4`
* 中型舰：长度 `3`
* 小型舰：长度 `2`

统一规则：

* 舰船宽度均为 `1`
* 只能横向或纵向摆放
* 不允许斜放
* 不允许重叠
* 允许相邻
* 不允许超出棋盘边界

## 10. 难度选择页需求

进入单人模式后，先进入难度选择页。

页面必须包含两个难度按钮：

* `简单`
* `困难`

每个按钮右侧必须有说明按钮：

* 图标可用 `!` 或 `i`
* 点击后弹出难度说明

### 10.1 难度说明文案

简单：

> 电脑会在所有未攻击过的格子中随机选择一个位置攻击，整体较容易。

困难：

> 电脑仍以随机攻击为基础，但会对玩家舰船所在格给予更高权重，命中概率更高。

说明：

* 困难模式不是 AI
* 困难模式是“带偏置的随机策略”
* 困难模式允许读取玩家舰船位置数据，并让这些格子的抽样权重提升为普通格子的 2 倍

点击难度按钮后进入部署阶段。

## 11. 部署阶段需求

部署阶段只显示玩家自己的棋盘。

### 11.1 界面元素

必须包含：

* 10×10 玩家棋盘
* 三艘待摆放舰船
* `随机` 按钮
* `开始` 按钮
* 当前难度提示
* 返回按钮

### 11.2 舰船摆放交互

必须支持：

* 拖动舰船到棋盘
* 自动吸附到最近格子
* 点击舰船一次，顺时针旋转 90 度
* 对于 1×N 舰船，本质上表现为横向 / 纵向切换
* 非法摆放时显示红色提示
* 非法摆放时不允许开始

### 11.3 合法性要求

玩家点击 `开始` 之前必须满足：

* 三艘舰船全部已摆入棋盘
* 没有越界
* 没有重叠
* 没有非法状态

否则：

* `开始` 按钮禁用
* 或点击后提示“请先完成合法部署”

### 11.4 随机部署

点击 `随机` 后：

* 系统自动生成玩家的合法布局
* 必须遵守与手动部署相同的规则
* 不允许重叠
* 允许相邻
* 不允许越界

### 11.5 机器部署

玩家点击 `开始` 后：

* 机器立即自动部署
* 机器部署必须合法
* 不允许重叠
* 允许相邻
* 不允许越界

## 12. 对战界面需求

对战界面采用竖屏上下双盘布局：

* 上方：敌方海域
* 下方：我方海域

### 12.1 界面元素

必须包含：

* 上方敌方 10×10 棋盘
* 下方我方 10×10 棋盘
* 当前回合提示
* 当前难度提示

### 12.2 显示规则

* 默认不显示敌方舰船初始位置
* 被攻击过的空格显示红色叉号

## 13. 攻击规则

### 13.1 先手规则

* 固定玩家先手

### 13.2 玩家攻击规则

* 玩家只能点击敌方海域进行攻击
* 命中后，玩家继续攻击
* 未命中后，玩家回合结束并切换到机器回合
* 若某格已攻击过，再次点击不消耗回合，并提示“该格已攻击”

### 13.3 机器攻击规则

* 机器只能攻击玩家海域
* 命中后继续攻击
* 未命中后结束机器回合
* 不允许重复攻击已攻击格子

### 13.4 沉没与结算规则

* 某艘舰船的全部格子被命中后，立即标记为沉没
* 一方全部舰船被击沉后，立即结算
* 玩家全灭：失败
* 机器全灭：胜利

## 14. 机器策略要求

本项目不引入 AI，只使用规则化随机策略。

### 14.1 简单模式

攻击逻辑：

* 在所有未被攻击过的格子中
* 每个格子的被选中概率相同
* 即标准随机点击

### 14.2 困难模式

攻击逻辑：

* 仍然在所有未被攻击过的格子中抽取
* 但对“玩家舰船实际所在格”的抽样权重提升为普通格子的 `2 倍`
* 普通空格权重为 `1`
* 玩家舰船格权重为 `2`
* 最终基于权重随机抽取一个目标格

这意味着：

* 困难模式下，机器更容易打中玩家舰船
* 但仍然是随机，不进行搜索，不做推理，不做连续追击策略优化

### 14.3 部署策略

简单模式和困难模式的部署都为：

* 纯随机合法部署

### 14.4 无需实现的内容

* 不需要思考延迟
* 不需要命中后优先邻格
* 不需要概率热力图可视化
* 不需要复杂推理
* 不需要搜索树

## 15. 音效要求

本版本必须加入最基础的游戏音效。

### 15.1 必须实现的音效类型

* `击中音效`
* `击沉音效`

### 15.2 播放规则

击中音效：

* 当任意一方命中对方舰船的某个格子时立即播放

击沉音效：

* 当任意一方击沉整艘舰船时立即播放
* 击沉音效优先级高于普通击中音效
* 若一次攻击同时触发“命中”和“击沉”，以击沉音效为最终表现

### 15.3 实现方式

优先建议：

* 使用本地短音频资源文件
  或
* 使用 Web Audio API 生成短促提示音

要求：

* 不依赖远程音频地址
* 音量受设置页总音量控制
* 默认开启
* 用户把音量拉到 0 时，不播放任何音效

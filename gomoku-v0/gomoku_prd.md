# Gomoku Lite PRD

## 1. 项目目标

开发一个基于 Web 的完整五子棋小游戏项目，项目名称为 `Gomoku Lite`。

该项目必须：

- 运行在现代浏览器中
- 同时兼容桌面端和移动端竖屏
- 采用 `React + Vite + Canvas API` 实现
- 交付为完整可运行工程，而不是代码片段
- 所有源码文件和文档统一采用 `UTF-8` 编码
- 所有界面文案统一使用简体中文，不允许乱码

该项目面向“即开即玩”的轻量小游戏场景，强调：

- 规则明确
- UI 简洁但完整
- 人机对战逻辑可感知地分级
- 模块结构清晰，便于未来扩展

## 6. 游戏规则

### 棋盘

- 棋盘大小：`15 x 15`
- 总格数：`225`

### 棋子定义

- `0` = 空
- `1` = 黑子
- `2` = 白子

### 基础规则

- 黑子先手
- 双方轮流落子
- 不允许落在已有棋子的位置
- 横向、纵向、左斜、右斜任意连续 5 子即为获胜
- 不启用禁手规则
- 不检测三三禁手
- 不检测四四禁手
- 不检测长连禁手
- 棋盘落满且无人形成五连则为平局

### 棋盘数据结构

```js
board[15][15]
```

### 落子历史

```js
moveHistory = [
  { x, y, player }
]
```

用于后续扩展悔棋功能。

## 7. 游戏模式

项目必须支持两种模式：

### 7.1 玩家对玩家（PVP）

规则：

- 玩家 1 使用黑子
- 玩家 2 使用白子
- 两人在同一设备轮流下棋

### 7.2 玩家对机器（PVE）

规则：

- 玩家使用黑子
- 机器使用白子
- 玩家先手
- 机器下棋前需要有 `200ms - 400ms` 的思考延迟
- 延迟可使用 `setTimeout`

---

## 8. 人机难度规则

这是本项目最重要的部分之一。难度必须在主菜单中可选，并且行为差异必须符合以下定义。

### 8.1 新手模式

机器行为规则：

- 机器只考虑自己的连线成长
- 如果机器当前一步可以直接形成五连，则立即落子获胜
- 如果当前没有直接获胜点，则优先选择更有利于自己连线的位置
- 新手模式不主动防守玩家
- 即使玩家下一步可能获胜，新手模式也不专门去堵

验收标准：

- 玩家能明显感受到新手机器经常“只顾自己下”

### 8.2 高手模式

机器行为规则：

- 机器只考虑防守玩家
- 如果玩家下一步有机会形成五连，则机器必须优先堵住
- 如果当前没有立即需要堵的点，则优先选择最能破坏玩家连线的位置
- 高手模式不主动追求自己的连线胜利
- 即使机器自己存在更强连线机会，也优先围绕防守玩家来落子

验收标准：

- 玩家能明显感受到高手模式“很会堵人”，但不会主动经营自己的胜势

### 8.3 专家模式

机器行为规则：

- 如果机器当前一步可以形成五连，则必须立即获胜
- 如果玩家下一步有机会形成五连，则必须立即堵住
- 如果没有立即获胜点，也没有立即防守点，则同时考虑：
  - 如何增强自己的连线
  - 如何破坏玩家的连线
- 专家模式既要进攻，也要防守
- 专家模式必须明显强于高手模式

验收标准：

- 玩家能明显感受到专家模式会主动做连线布局，同时也会防守

### 8.4 难度 UI 要求

主菜单必须支持：

- 直接开始 `PVP`
- 选择 `PVE` 时必须进一步选择：
  - 新手
  - 高手
  - 专家

状态栏必须显示当前人机难度。

## 9. 游戏状态机

游戏必须包含以下状态：

- `MENU`
- `PLAYING`
- `GAME_OVER`

状态流转：

```text
MENU
→ 选择模式
→ PLAYING
→ 胜利 / 平局
→ GAME_OVER
→ 重新开始 / 返回菜单
```

必须由 `GameManager` 统一控制状态切换。

## 11. Canvas 棋盘要求

棋盘必须使用 Canvas 绘制，而不是纯 DOM 表格。

棋盘绘制要求：

- 绘制 15x15 网格
- 绘制五子棋常用星位点
- 绘制黑白棋子
- 支持鼠标或触摸点击落子
- 鼠标悬停时允许显示轻微落点提示
- 获胜后应高亮获胜连线

性能要求：

- 15x15 棋盘下交互应流畅
- 不需要复杂动画
- Canvas 重绘逻辑要清晰稳定

## 12. 音频要求

### 12.1 背景音乐

- 不需要背景音乐
- 不要生成循环背景旋律
- 不要生成背景噪声或持续播放音

### 12.2 必须保留的音效

- 按钮点击音效
- 落子音效
- 胜利音效

### 12.3 音效实现方式

- 允许使用 Web Audio API 直接生成简单音效
- 不强制提供 mp3 / wav 文件

### 12.4 音量要求

- 落子音效必须明显可感知
- 落子音效音量应明显高于按钮点击音效
- 当前实现目标：落子音效比默认轻量提示音高很多
- 胜利音效应清晰但不要刺耳

### 12.5 声音控制

- 必须支持声音开启 / 关闭
- 用户关闭声音后不应再播放任何音效
